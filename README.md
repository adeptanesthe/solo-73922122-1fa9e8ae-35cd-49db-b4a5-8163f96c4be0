# 路面裂缝两层卷积 · 边缘分块尺寸选型 + 复核定点修正

FastAPI + NumPy（全程 float64）实现的网页小工具，包含两个相互独立的功能：

1. **分块选型（`/`）**：上传一张每边至多 512 像素的灰度 PNG 和两层卷积的
   权重/偏置 JSON，在给定的第一层输入激活预算下，从 1～64 中选出预算允许的
   最大**方形输出分块边长**，并分别用分块推理和独立整图基准跑分，报告峰值
   用量、最大绝对误差及其坐标，误差 > 1e-8 判失败。
2. **复核修正（`/refine`）**：上传 1～2 张每边至多 128 像素的灰度 PNG 和现有
   权重 JSON，在各图模型输出网格上对最多 32 个点标注裂缝/非裂缝/保留原分数，
   冻结首层、只微调第二层卷积，求满足全部判定约束且参数改变量平方和最小的解，
   重新载入并整图推理复查通过（约束误差 ≤ 1e-8）后才开放新权重下载。

## 网络结构（固定）

| 层 | 通道 | 核 | 步长 | 膨胀 | 零填充 | 激活 |
|---|---|---|---|---|---|---|
| layer1 | 1 → 4 | 3×3 | 2 | 1 | 1 | ReLU |
| layer2 | 4 → 1 | 3×3 | 1 | 2 | 2 | — |

## 复核修正（/refine）的建模与口径

- 冻结 layer1（权重、偏置逐位不变），可调参数仅 layer2 的 36 个权重 + 1 个
  偏置，共 37 个。冻结 layer1 后，任一点的 layer2 分数对这些参数是**线性**的：
  `s_p(d) = s0_p + F_p·d`，其中 `F_p` 为该点各 tap 的 layer1 激活（图外按
  零填充），与整图基准 `run_full_baseline` 同一计算路径。
- 标注约束（d 为参数改变量）：
  - **裂缝**：修正后分数 `≥ 0.1`；
  - **非裂缝**：修正后分数 `≤ −0.1`；
  - **保留原分数**：`F_p·d = 0`，整图推理复查时要求新旧分数差 `≤ 1e-8`。
- 标点合计最多 32 个，修正点（裂缝/非裂缝）与保留点各至少 1 个，同图坐标
  不可重复，坐标必须落在该图输出网格内。
- 目标 `min ‖d‖²` 配合线性约束是凸二次规划（Hessian 为单位阵，解唯一）：
  先用 HiGHS 线性规划严格判定可行性，再用 SLSQP 求最小范数解，求解器内部
  容差 1e-10。不可行时返回原因（含距目标差距最大的约束），不产出权重。
- 新权重按原 JSON 嵌套格式（`layer1`/`layer2` 各含 `weight`/`bias`）写回；
  落盘前模拟“写 JSON → 重新载入 → 整图推理”，对全部标点逐一复查，最大约束
  违例 `≤ 1e-8` 才**原子发布**到下载目录；否则撤下旧下载、不提供新文件。
  用户当次上传的原权重只存在于请求内存中，不会被改写。
- 发布产物保存在 `REFINE_DATA_DIR`（容器内 `/data`，docker compose 命名卷
  持久化），全局只保留最新一份通过复查的 `refined_weights.json`。

### /refine 的 HTTP 接口

| 方法与路径 | 作用 |
|---|---|
| `GET /refine` | 修正页面 |
| `POST /refine/prepare` | 上传 1～2 张 PNG + 权重，返回各图尺寸、输出网格与原分数网格 |
| `POST /refine/solve` | 表单追加 `points`（JSON 数组，元素含 `image_index/row/col/label`），求解并复查 |
| `GET /refine/download` | 下载当前通过复查的权重；无产物时 404 |

`label` 取值：`crack`（裂缝）、`noncrack`（非裂缝）、`keep`（保留原分数）。

## 预算口径与选型规则

- 对每个输出分块（边缘块按实际输出尺寸**裁短**），沿两层感受野链路反推出
  覆盖它所需的**图内激活最小矩形窗口**，元素数 = 窗口高 × 窗口宽 × 输入通道数；
  图外零填充不物化、不计入。
- 窗口公式（layer2 dilation 2 使单输出在 layer1 输出上跨度 `[i−2, i+2]`，
  layer1 stride 2 再映射到输入）：
  行窗口 `[2·r0−5, 2·(r1−1)+6)`，列窗口同理，最后裁到图界。
- 边长 `s` 的峰值 = 该 s 下所有分块窗口元素数的最大值（内部块通常最大，
  边缘块被图界裁短）。从 1～64 中选峰值 ≤ 预算的最大 s。
- 实跑时分块路径截取的正是同一窗口；流水线对“实跑峰值 == 规划峰值且
  ≤ 预算”做硬性断言，守住预算。
- 当单像素块（s=1）仍超预算时，**不执行推理**，只返回最低所需预算。

## 运行方式

### Docker Compose（推荐）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

### 本地 Python（3.11+）

```bash
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### 权重 JSON 格式

```json
{
  "layer1": {"weight": [[[[...3x3...]]]], "bias": [0, 0, 0, 0]},
  "layer2": {"weight": [...形状 1x4x3x3...], "bias": [0]}
}
```
形状要求：layer1.weight `(4,1,3,3)`、layer1.bias `(4,)`、
layer2.weight `(1,4,3,3)`、layer2.bias `(1,)`。

### 样例

`scripts/make_samples.py` 生成确定性样例（已随仓库提供于 `samples/`）：

```bash
python3 -I scripts/make_samples.py samples
# sample_crack_64.png（64×64 裂缝灰度图）
# sample_random_8.png（8×8 随机图，便于手工核对窗口）
# weights.json（两层权重与偏置）
```

页面上传两个文件并填入预算（元素数）即可；勾选“以 JSON 返回”便于脚本调用。
